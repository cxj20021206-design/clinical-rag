## 4. 今天的技术改动与实测发现

### 4.1 `evidence.py`（新）：引文核验做成硬门

LLM 会改写引文——调标点、补缩写、把 PDF 抽错的字母拼回正确单词。这些改写读起来
毫无破绽，**人工确认层看不出来，只有 `str.find` 看得出来**。

规则：**quote 定位不到 → 该字段判 `not_extracted`（硬错误，不得进检索）。**

两档归一化是拿 6 张卡的 27 条引文实测逼出来的：

| 归一化 | 定位成功 |
|---|---|
| 仅折叠空白 | 20/27 |
| 第一档：Unicode 破折号/撇号/空格族 + 跨行断字缝合 | 23/27 |
| 第二档：只保留字母数字 | 25/27 |
| 第二档 + 修掉卡自身的省略号 | **27/27** ✅ |

三类 PDF 伪影（`corpus/README` 那句"零连字丢失"只覆盖了第一类）：

1. **Unicode 同形字符**：`children aged 1−59 months` 里的 `−` 是 **U+2212 数学减号**，
   `59` 与 `months` 之间是 U+2009 窄空格，`Alzheimerʼs` 用 U+02BC。
2. **字间空格污染**：cardiac MRI 有整段被抽成 `h yp er tr ophic c ar-\ndi om yo path`。
   **第一档救不了**——模型会自行拼回正确单词，而那个字符串原文里不存在。
3. **省略号**：唯二失败的两条是**卡自己**写了 `(sensitivity 55.5% ...)`。
   这已不是逐字引用，两档都不该救 → 已做成 `validate_card` 硬错误。

**页码由程序从 PDF 反查**，不让模型填（错页码是"最像正确"的错）。

### 4.2 `evidence_stage` 改成"模型报事实 + 程序映射"

模型只填 `evidence_basis` 七个可观测事实，程序按判定表映射 C0–C4
（`claim_card.stage_from_basis()`）。理由：C1/C2 界线人读都含糊；stage 错一级整条路由
全错；分级映射是策略必须可审计。**只接入不消费**——不一致只报警不覆盖。
自测与 6 张基准卡的分级逐条吻合（C4/C4/C2/C2/C2/C0）。

### 4.4 解析层：MinerU 上了，而且它改变了证据链

登录节点跑不动（CPU worker 被 `BrokenProcessPool` 杀；默认 vlm 后端还会尝试起本地服务
并超时），必须 `sbatch` 到 GPU 节点跑 `-b pipeline -d cuda`：**15 页 / 9 分钟 / 1 张 A100**。

实测三个差异（详见 `sample/dkd_retinal_ldh/01_parse/parse_notes.md`）：

**① 表格在 pypdf/pdfplumber 下是逐字符逆序的**：`Sex`→`xeS`、`(27·04%)`→`)%40⋅72(`。
MinerU 把它还原成结构化 HTML（十个外部数据集的名称、种族构成、平均年龄全部可读）。

**② 表格内容在 pypdf 文本里根本不存在**：`Number of participants with diabetes`、
各数据集平均年龄 `66.05`，pypdf 全查不到。→ 由此定下新规矩并已实现
（`SourceDoc.from_mineru`）：**`provenance.source` 必须指向抽卡时实际读的那份解析产物**。
拿 MinerU 抽卡却用 pypdf 核验，表格来源的引文会被判定位失败 → 标成 `not_extracted`
（硬错误）→ **把解析层的能力差异误报成抽取故障**。
改用 MinerU 源后两张卡 13/13 定位成功，且多数从 `normalized` 升到 `exact` 档。

**③ 表格结构对了，单元格顺序仍可能交错**：年龄行被上一行的百分比穿插成
`Age, years (45.34%) 66.05`。事实可读、可用于推断 `adult`，但**给不出可逐字引用的连续
片段** → 按 `stage2 §⑩` 保留 `inferred` 且**不给 quote**，note 写清依据。
宁可不给，也不拿交错拼出来的字符串冒充原文。

**最值得注意的是**：Q6（issue）被解决、Q7（cannot_determine）拿到主文级证据，
**不是重新核查得来的，是换了解析层得来的**——同一张卡、同一套 prompt。
→ 解析层不是预处理细节，是证据链的第一环。

## 6. 现在能做什么 / 还不能做什么

**能**：给一篇 PDF（任意期刊），走完 **MinerU 版面解析** → 概览 → 多张卡 → 反方核查
→ 检索 → 审稿要点，每一步产物都带可定位到页码的原文出处，不适用的清单会打印拦截理由。

**不能**：
- **补充材料一份都没有**（`journals/` 下 `find -iname '*supp*'` 零命中）。
  本次样例的 appendix 未获取，已如实标 `input_coverage: included: false`
- **normative 覆盖不了糖尿病肾病**（同心衰/糖网/AKI，两条通道都补不上）。
  本次样例 normative 命中 **0 条**——这是真实缺口，不是故障
- 判断论文**实际证明了什么**（内部原文核验，另一个子系统，一直没动）
- 抽卡还没有自动化脚本：`prompts/` 是给执行者（我）看的指令，跑一篇要人来触发
- **解析不是随手能跑的一步**：MinerU 必须上 GPU 节点排队，登录节点会被杀
