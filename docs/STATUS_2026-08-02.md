## 4. 撞出并修掉的三个既存缺陷

都不是新 prompt 引入的，是**新 prompt 的卡第一次走到那些分支**才暴露。

### ① `validate_card()` 与 stage2 规则⑨直接打架 → 新卡一律过不了门

规则⑨明令 `evidence_stage` 留空、由程序从 `evidence_basis` 七事实映射；
而校验器仍硬性要求它 ∈ C0–C4。既有卡全出自旧 prompt、自己写了 `"C2"`，所以一直没暴露。

修法（`claim_card.py`）：留空 → 用映射填上并记 warn 注明"此值来自程序判定表"；
**已声明的仍只报警不覆盖**（"只接入不消费"对声明值不变）。

### ② `evidence.py: from_mineru()` 漏读一半块类型 → 合法引文被判成系统故障

只读 `("text","table_body","table_caption","img_caption")`，而 MinerU 3.x 用的是
**`image_caption`（不是 `img_caption`）**、`chart_caption`、`chart_footnote`、`content`、
`table_footnote`、`code_body`、`list_items`。ICLR 篇有 7 chart + 3 image，**图注整体缺失**。

后果：模型从图注取的合法引文定位失败 → 判 `not_extracted`（硬错误）→ 按流程要退回重填
一张本来正确的卡。**这与"拿 MinerU 抽卡却用 pypdf 核验"同类，只是发生在 MinerU 内部。**

修法：白名单 + **未知键告警**（schema 变了会吵，不再悄悄变窄），实测告警可触发。

### ③ 研究设计推断用裸子串 → `ct` 命中 `characters`

`_IMAGING_KW` 的 `"ct"` 命中 ICLR 卡 `model_input` 里的 `"chara`**`ct`**`ers"`，
把一篇**血糖时序**论文判成 `medical_imaging_ai` → CLAIM 影像清单被错误启用、
报成 🕳（适用但零摄入＝真缺口）→ **凭空撑大缺口报告**。
更糟的是 `"predi`**`ct`**`ion"` 同样含 `ct`，**几乎任何预测模型论文都会中招**。

修法：缩写（≤3 字符）首尾封边界，词干只封词首。与 §6e 的 `injury`、§6d 的
`ultrasound` 是同一类错误 —— **短词当判别信号必须先划边界**。

## 8. §5-A 的落地（2026-08-01，方案 (a)）

**一句话**：给投稿日阶梯加第 5 档 `venue_deadline` —— 会议截止日由**人**维护在
一张表里，程序机械查表补入，**模型一次都不许推断这个日期**。

| 动的东西 | 改了什么 |
|---|---|
| `venue_deadlines.yaml`（新，仓库根） | 运维方维护的「会议 → 年份 → 截止日」表。文件头写死三条规矩、已知粗糙之处、怎么加一届。**2026-08-02 扩到 7 个会议 14 届**（iclr 2023-2026 / neurips 2023-2025 / icml 2024-2025 / miccai 2024-2025 / midl 2025 / chil 2026 / mlhc 2026），每届都带实际抓过的 `source_url` 与页面原文引句；规矩 1 同日修订为「禁凭记忆推断、允许抓官方页面代填但须在 `verified_by` 标明未经人工复核」。ICLR 2024 由 `2023-09-22` 订正为 **`2023-09-23`** |
| `claim_card.py` | 新增 `SUBMISSION_DATE_BASES` 五档枚举 + `resolve_venue_deadline()`（**纯查表，零推断**）；`validate_card()` 认 `submission_date_source`，并**拿卡上的日期与表逐字比对** |
| `extract.py stamp-date`（新子命令） | 读 `00_source/metadata.yaml` 的 venue/year → 查表 → 行级写进卡（保留卡里的注释）。**只补 `submission_date` 为空的卡**：论文自带 `Received` 时那是每篇各自的真实日期，优先级高于"全会议一个常数"。**2026-08-02 补一条订正通道**：卡上已是 `basis: venue_deadline` 的日期，其来源本就是表而非论文，表被订正时随表更新（先判 basis 再判有没有日期）——否则改表就只剩"手工改卡"一条路，而那正是逐字比对要禁的 |
| `prompts/stage1_overview.md` §③ | 阶梯表下方写明第 4 档之后由程序接手，并**明令模型不得推断该日期**（凭记忆、拿参考文献年份反推、按"看起来是哪年的"估，全部禁止） |

**为什么日期要与表逐字比对**（这一步是整条通道能成立的关键）：没有它，
`venue_deadline` 就退化成"允许手工往卡里敲一个日期"。而错误的投稿日会让整批
`predates` 判定悄悄反向，**结果看起来完全正常** —— 同"页码由程序给、模型不要填"。
实测四条路径：正常✓ / 手工改日期✗ / 会议未登记✗ / basis 乱写✗。

**为什么取更早的一档（摘要截止而非正文截止）**：日期越早 → 越多指南被判成
"投稿时尚不存在" → 越少拿标准去要求作者 → **安全侧**。反过来填晚了就是拿作者
当时看不到的标准指责他（同 SPEC §10「取 Received 不取 Published」）。
