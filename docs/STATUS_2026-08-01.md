### 为什么是 bundle + 可插拔后端，而不是直接调 API

仓库里没有任何 LLM 调用代码，环境也没有 `anthropic` 包和 API key。与其写一段没跑过的
API 代码，不如把"一次调用所需的全部输入"物化成 `request.md` + `manifest.yaml`，
再交给后端：`bundle`（只装配，人可贴进任何会话）/ `claude-cli`（`claude -p`，新进程）/
`exec`（任意外部命令）。**隔离于是成了操作系统给的，不是靠模型自律。**

无论走哪个后端，阶段二产物都要过同一道 ③④ 硬门（`evidence.verify_card` +
`claim_card.validate_card`），不过就退非零并要求**回阶段二重填**。

### 三件今天才知道的事

**① 装配时抓到一处真实泄漏。** 第一版把 `prompts/README.md` 整个塞进阶段三的 bundle，
而 README 第 8 行拿 **LDH 那篇**当反例讲流程事故——那正是被审的这篇论文。核查者读到会
先入为主。已改成只截"三条硬约束"之后的部分。
→ **隔离不是"别给上一阶段的产物"，是"别给任何关于这篇论文的场外信息"**，
而这条只有把材料真正物化成文件、再去 grep 它的时候才会被发现。

**② 模型自报的隔离状态两个方向都错。** 六次运行全部跑在独立进程里，三次在正文里自报了
`context_isolated`：两次 `true`、**一次 `false`**。它无从知道自己被怎么调起来的。
→ `land()` 现在把正文里该字段剥掉并在头部留痕。`context_isolated` 是**三值**：
`true`（程序开的独立进程）/ `asserted`（driver 之外安排的隔离，程序没证明）/ `false`。

**③ 模型读 md，程序核验 `content_list.json`。** 两者是同一次 MinerU 解析的两种序列化
（程序强制同目录）。模型读 md 因为它可读；核验用 content_list 因为它带 `page_idx`。
manifest 里 `model_read` / `verified_against` 分开记，不合并成一个 `source`。

## 3. 隔离核查的结果（待决 B 的答复）

6 次独立调用，45 条 findings：**21 pass / 20 issue（h1 m9 l10）/ 4 cannot_determine**。
非隔离那次是 7 条、4 个 issue。完整对比见 `ISOLATION_COMPARISON.md`。

### 3.1 隔离挑出了非隔离判 pass 的那一问，而它正是本项目的核心

非隔离把**第 4 问（性能提升当患者获益）判成 pass**。隔离后两张卡各自都判出 issue：

- `claim_1` `demonstrated_effect` **只报敏感度不报特异度**——而卡声称的获益是"分流谁去做
  确证化验"，分流的代价恰由特异度承担（同一操作点 47·6% vs 38·8%，**p=0·072 不显著**；
  外部集低至 31·7%）。
- `claim_1` 论文断言 `cost-effective`，全文**无任何成本分析**（论文还恰恰以
  "nor shown to be cost-effective"否定过前人工作——同一判据对己方未执行）。
- `claim_2` `claimed_benefit` 写"减少**不必要的**侵入性肾活检"，原文只说
  `minimise the need for invasive kidney biopsy`。**"不必要的"是卡自己加的定语。**

同一个上下文里，核查者刚写完 `benefit_gap`，再问它"`benefit_gap` 写对了吗"，它答"对"。

### 3.2 ⚠️ 隔离**推翻**了昨天那条唯一的 high

昨天判：`comparator` 把自建算法对照与**文献引用的**尿试纸敏感度并列，"论文并未在同一
人群里与试纸做头对头比较"，严重度 high，并据此提出待决 C（拆 `comparator` 字段）。

隔离运行判该问 **pass**。核对原文，隔离运行是对的：

> Methods：`We also compared the performance of the DeepDKD system and urine dipstick protein test in DKD screening (appendix p 29).`
> Results：`Among two external validation datasets (NDSP and PUDM), the sensitivity of DeepDKD (77⋅8% in both datasets) was substantially higher than that of the urine dipstick protein test (19⋅8% vs 0%).`

**主文里有头对头的数字。** 昨天抓的 43·6%–69·4% 是 Introduction 引自文献 10–12 的背景
数字。→ **待决 C 的前提不成立**（见 §4）。

### 3.3 隔离运行之间"抓到什么"稳定，"抓到多少 / 判多重"不稳定

`q4`/`q7` 各跑过两次机制不同的隔离运行（子上下文 / `claude -p`）：`claim_2_q7`
**逐条一致**；`claim_1_q7`、`claim_2_q4`、`claim_2_q12356` 都是**核心发现一致、
严重度或覆盖面不一致**（同一条被判 medium 与 low、或一次报 3 条一次报 1 条）。
→ **评测能当指标的是"发现的集合"，不是条数和严重度。**

### 3.4 隔离新挑出的其他要害（各卡详见 `isolated/*.yaml`）

- `claim_2` **high**：`population.age_group` 的 note **借用了 claim_1 的队列年龄**——
  主文那张表只覆盖 claim_1 的十个队列，claim_2 的队列特征在未获取的 appendix pp 15–16。
- `claim_2`：把**参考标准**（肾活检）写成了 `comparator`。claim_2 真正做过统计比较的
  只有算法对算法；论文自陈的现行做法（按视网膜病变状态鉴别）从未当基线跑过。
- `claim_2`：`population.special: biopsy-confirmed` 是**样本入组来源**，而卡的
  `intended_use` 是"用在尚未活检、正在考虑是否活检的患者"——两者是互斥人群。
- `claim_1`：`prospective: true` 与 `different_site: true` **由不重叠的证据支撑**
  （多站点证据全部回顾性；前瞻证据只有上海一家基层中心，可能与开发数据同源）。
  两个 true 并列读会读出"多站点前瞻研究"——论文里不存在。
