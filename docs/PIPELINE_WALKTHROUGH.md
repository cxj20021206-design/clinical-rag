## 0. 我们到底在干什么

给一篇医学 AI 论文当审稿人，并且指出：**按现实医学界的标准，它本来应该证明什么。**

比如一篇论文说"我的 AI 看眼底照片就能筛查糖尿病肾病"。要审它，得先知道
**医学界对"糖尿病肾病筛查"这件事已经有什么规定** —— 那些规定写在 WHO 指南、
美国预防服务工作组（USPSTF）建议、各国学会临床指南、报告规范清单里。
我们已经把这些抓下来存成了一个库。

**铁律**（整个项目的地基，任何一步都不许破）：

| 铁律 | 意思 |
|---|---|
| 外部源只回答"应该证明什么" | "论文实际做到了什么"是**另一个子系统**（内部原文核验），不许混 |
| `predates_paper_submission` | 投稿之后才发布的标准，**不得用来指责作者** |
| `verbatim: true` | 库里每条标准都逐字来自原文，卡里每条引文也是 |
| 只用开放许可内容 | 拿不到许可的指南（如 NICE、SSC）宁可不收，并在缺口里如实标明 |

## 1. 为什么中间要有一张"卡"

程序不能直接拿 PDF 去查指南库。库里每份指南都标了"我管什么病、管什么人群、
管什么场景"，所以论文这边也得有一份**对应格式的标签表**，两边才对得上。

**这张标签表就是 Claim Card（临床主张卡）。**

一句话：**卡 = 把一篇论文压缩成一张结构化表格，好让程序拿它去库里查。**

难在这张表**只有读懂了论文才填得出来** —— PDF 里没有"本论文的临床任务=筛查"
这种字段。而填错一格，程序就会去查错的指南，或者什么都查不到。
下面整条流程要解决的就是这件事。

## 3. 上游七步，逐步讲

### ① PDF → 纯文本（程序）

模型读不了 PDF，得先转字。**但这一步远不是"把 PDF 转成字"那么简单。**

实测（`sample/dkd_retinal_ldh/01_parse/parse_notes.md`）：

- `pypdf` / `pdfplumber` 把某些表格抽成**逐字符逆序** —— `Sex` → `xeS`，
  `(27·04%)` → `)%40⋅72(`；
- 更糟的是，表格里的内容在 pypdf 文本里**根本不存在** ——
  `Number of participants with diabetes`、各数据集平均年龄 `66.05`，搜都搜不到；
- MinerU（版面解析）把它还原成结构化 HTML 表格。

由此定下一条规矩，写进了 `evidence.py`：

> **`provenance.source` 必须指向抽卡时实际读的那份解析产物。**

指错了会让**解析层的能力差异被误报成抽取故障** —— 拿 MinerU 抽的卡、却用 pypdf
文本核验，表格来源的引文会定位失败，被标成"抽取故障"，而其实是解析工具的差别。

**成本**：登录节点跑不动（CPU worker 被 `BrokenProcessPool` 杀；默认 vlm 后端会起
本地服务并超时），必须 `sbatch` 到 GPU 节点跑 `-b pipeline -d cuda`，
15 页约 12 分钟 / 1×A100。作业脚本见 [`../sample/_parse_job.sbatch`](../sample/_parse_job.sbatch)。

> **解析层是证据链的第一环，不是预处理细节。** 上一轮有两个核查结论
> （`age_group` 的依据、`different_site` 能否核实）是**换了解析层才解决的**，
> 不是重新核查得来的。

### ② 通读全文（模型第 1 次）—— `prompts/stage1_overview.md`

**不填卡**，先搞清楚论文整体在做什么。七个问题：

1. 原创研究还是综述？（不是原创就停在这一步，且要写明这是**"不适用"而非"不匹配"**）
2. 有几个**独立的**临床主张？
3. 各涉及什么病、什么人、什么任务？
4. 有哪些研究队列？**每批人是怎么被选进来的、有没有额外的亚组限制？**
5. 每个队列是开发用、内部验证、外部验证，还是真的部署了？
6. 每个主张的**标准答案（参考标准）从哪来**？（病理？随访结局？另一项检查？专家判读？）
7. 论文自陈的**现行临床做法**是什么？有没有真的拿它当对照跑过？

**这一步的产物是下一步的约束，不是参考资料。** 两条硬规矩：

- **`uses_cohorts` 是排他清单**。阶段二填某张卡时，只允许引用该 claim 名下列出的队列。
  漏列 → 阶段二无据可填、标 `not_extracted` 停下（**安全侧**）；
  多列 → 阶段二会拿**别的主张的人群和数字**来填这张卡，而且**成卡之后看不出来**
  （每个数字单独看都是论文里真实存在的）。
- **`unavailable_content` 是禁令**。附录没拿到就登记清楚，阶段二遇到落在里面的内容
  只能标 `not_extracted`，不许用主文里别的队列的表来代替。

第 6、7 问是后加的，因为 `comparator` 这一格有**三个候选占位者**
（参考标准 / 算法对照 / 现行做法），阶段二一次只读一个 claim，分不清谁是谁。
在阶段一把三者拆成三个字段登记，阶段二就只是搬运。

### ③ 填卡（模型第 2 次，有几个主张跑几次）—— `prompts/stage2_fill_card.md`

输入 = 论文全文 + 阶段一的 overview + "这次填哪个主张"。输出 = **一张**卡。

模型把格子逐个填上，**每填一格都要从原文摘一句原话当证据**。

这份指令的绝大部分内容是在堵坑。最典型的四条：

- **病种格不得被污染。** 只许写病名，不许写 "AI 辅助的"、"低剂量 CT 的"、
  "高危人群的"、"筛查用的"。写脏了程序匹配不上，**而且不报错**，看起来像"库里没有这个病"。
- **被程序消费的字段必须写英文。** 见 §6 那张表。写中文不报错，只**静默失效**。
- **证据阶段（C0–C4）不许模型自己判。** 模型只报七个可观测事实
  （有没有临床主张 / 有没有外部队列 / 是不是别的机构 / 是不是前瞻设计 / 有没有随机 /
  模型输出有没有真的改变照护 / 主要终点是模型指标还是临床结局），
  **程序按判定表映射**成 C0–C4。理由：C1/C2 界线人读都含糊，分级错一级整条路由全错，
  而分级是策略、必须可审计。
- **情态动词句不能支撑门控字段。** `could` / `eventually` / `has the potential to`
  所在的句子讲的是作者的设想，只能进 `future_intent`。

### ④ 引文核验（程序）—— `evidence.py`

**这一步是机械活，但抓到的问题最扎实。**

规则：每条引文，程序拿去原文里 `str.find` 搜一遍，**一个字符一个字符地比**。
搜不到 → 该字段判 `not_extracted`（硬错误，卡不许进检索）。

**为什么必须是程序**：大模型**会不自觉地改写引文** —— 调标点、补缩写、把 PDF 抽错的
字母拼回正确单词。改完读起来通顺、贴切、完全符合原意，**人工审核根本看不出来**。
只有 `str.find` 看得出来。

实测：6 张卡的 27 条引文，**一条都没有原样对上**。所以有了三档匹配：

| 档 | 洗掉什么 | 用来救什么 |
|---|---|---|
| `exact` | 什么都不洗 | — |
| `normalized` | 各种破折号/撇号/引号/空格统一、合字拆开、跨行断字缝合、大小写统一 | Unicode 同形字符（`1−59` 里是 U+2212 数学减号；`Alzheimerʼs` 用 U+02BC；`artiﬁcial` 是 ﬁ 合字） |
| `alnum` | **只留字母和数字**，标点空格全丢 | **字间空格污染**（整段被抽成 `h yp er tr ophic c ar-di om yo path`；模型会自行拼回正确单词，而那字符串原文里不存在） |

两条配套规矩：

- **归一化只发生在程序内部的临时副本上。** 落盘的引文一个字节不改 ——
  合字、烂空格照样留在卡里。**造出原文没有的词是 verbatim 违规，留下可辨认的伪影不是。**
- **模型不许自己"顺手修好"。** 一旦它开始修，就再也分不清"这句话是真从原文来的
  （只是排版烂）"和"这句话是模型编的（编得很像）"。

**省略号一律硬拒绝**，连试都不试。因为一旦有省略号，这句话在原文里就不连续了 ——
你只能证明前半截在、后半截也在，**证明不了它俩挨着，更证明不了中间被删的不是关键限定**。
（原文"敏感度 95%，**但在成人中仅 42%**，因此不建议用于成人"，加个省略号能拼出任何意思。）

**太短的引文也拒绝**（归一化后 < 12 字符）：`adults` 在任何论文里都搜得到，定位成功也证明不了什么。

**页码由这一层给，不让模型填。** 模型填页码基本必错，而错页码是"最像正确"的那种错。

### ④b 投稿日：会议论文的特例（程序）—— `venue_deadlines.yaml`

`predates` 是全系统唯一的硬门控，它要一个**论文投稿日**。期刊论文首页有
`Received:`，会议的匿名送审稿**一个日期都没有** —— 阶段一的四档阶梯全落空，
卡进不了检索。而 ICLR 的 MedAI 论文正是 MVP 的目标语料。

第 5 档 `venue_deadline` 就是为这个加的：**日期不来自论文，来自会议日程**，
由人维护在 `venue_deadlines.yaml`，`extract.py stamp-date` 查表机械补入。

三条规矩：

- **模型不得推断它，一次都不行。** 问模型"ICLR 2024 什么时候截止"，它会给一个
  看起来很像的日期，而**猜错了没有任何地方会报错** —— 错日期会让整批 `predates`
  判定悄悄反向，结果看起来完全正常（同"页码不让模型填"）。
- **卡上的日期与表逐字比对**，对不上就是硬错误。没有这一步，这一档就退化成
  "允许手工往卡里敲个日期"。
- **取更早的一档**（有摘要截止就用摘要截止）：日期越早 → 越少指南被判成
  "投稿时已存在" → 越少拿标准去要求作者 → 安全侧。

粗糙之处要说得出口：这是"每会议每年一个常数"，不是每篇各自的投稿时刻。
论文自带 `Received` 时以论文的为准。

### ⑤ 规则校验（程序）—— `claim_card.py`

枚举值合法性、逻辑自洽。病种格混进模态词/任务词 → 硬错误。

> ④⑤ 不过就**退回③重填，不许手工改卡去迁就校验** ——
> 手改等于把"抽取故障"洗成"论文没写"，而这两件事后果相反（见 §7）。

### ⑥ 反方核查（模型第 3 次，**新进程**）—— `prompts/stage3_adversarial_check.md`

给它：**卡 + 论文全文 + 挑错指令**。
不给它：阶段一/二的产物、任何以前对这篇论文的分析、任何点名这篇论文的文档。

**为什么必须换新会话**：同一个上下文里，模型刚写完"这格我这样填是因为……"，
你再问它对不对，它会顺着自己走（同血统偏好）。实测：

- 同一张卡，非隔离 1 次出 7 条发现 / 4 个问题；隔离 6 次出 45 条 / 20 个问题；
- 有一问（是不是把模型性能提升当成了患者获益）**非隔离判"通过"，两次隔离各自都判出问题**；
- **隔离推翻了非隔离唯一那条 high** —— 非隔离说"没跟现行做法头对头比过"，
  隔离跑完发现主文里**有**头对头数字，非隔离抓的是引言引自文献的背景数字；
- 隔离运行之间**"抓到什么"稳定，"抓到多少/判多重"不稳定**
  → **下游只能采信发现的集合，不能采信条数与严重度。**

隔离怎么保证：`extract.py --backend claude-cli` **开一个新的操作系统进程**，
并且组装材料走**白名单**（`STAGE_SPEC["3"]["needs"] = []`，组装函数根本不去读
`02_overview/`）。不是"我记得不给它"，是程序上够不着。

指令开头还有一段反直觉的内容：**九条"填卡约定"，告诉核查者哪些不是错**
（比如 `care_setting` 该空就空、纯基准论文照样要出卡）。不给它，它会把
"按约定填对了"报成错误。而这九条**刻意不用 `CARD_EXTRACTION_SPEC.md` 原文** ——
那份文档逐条点名它归纳的 6 篇论文，被审论文若在其中就是循环论证。

> **踩过的坑**：第一版组装时把 `prompts/README.md` 整个塞了进去，而那份 README
> 拿被审的那篇论文当反例讲流程事故。**隔离不是"别给上一阶段产物"，是"别给任何
> 关于这篇论文的场外信息"。** 现在装配时会 `_audit_stage3_leak()` 自动扫，命中即硬退出。

## 4. 卡的三层

规矩只有一句：**只有第一层参与"哪份指南适用"的判断。**

| 层 | 装什么 | 格式 |
|---|---|---|
| `gating` | 病种、人群、场景、任务、证据阶段、七个事实 | **受控枚举**，取值只能从固定清单里选 |
| `descriptive` | 论文的医学细节：多少人、什么终点、作者声称什么好处、实际证明了什么、差距在哪 | 自由文本 |
| `provenance` | 每一格的证据：引文原文、位置、状态 | 结构化 |

**为什么非分不可** —— 三个真实翻车例子（都是拿库里真实指南跑出来的）：

1. 病种格写 `acute kidney injury in critical illness`（听起来更准确了）
   → 因 `critical illness` **命中一份新生儿超声指南**；
2. 写 `excluding hemorrhagic stroke and congenital heart disease`
   → `congenital heart` 反被当成**命中**（词面匹配读不出否定）；
3. `intended_use` 里写了一个 `triage` → USPSTF 场景门整个拦下，
   一篇糖网**筛查**论文因为把决策写清楚了，反而拿不到筛查指南。

结论不是"别写细节"，而是：**细节要写，但不能写进准入层。**

## 5. 一篇论文为什么会出多张卡

拆卡的判据**不是数病种个数或任务个数**，而是：
**论文自己有没有为这件事做单独的临床声明？**
可操作信号四条 —— 有自己的队列、有自己的人群、有自己的对照、有自己的终点。
满足两条以上就拆。

`sample/dkd_retinal_ldh/` 那篇（同一个 AI、同样看眼底照片）拆出两张：

| | claim_1 筛查 | claim_2 鉴别诊断 |
|---|---|---|
| 病种 | diabetic kidney disease | diabetic nephropathy（+ subtype） |
| 人群 | 糖尿病人 | **已做过肾活检者** |
| 场景 | primary_care | outpatient_specialty |
| 任务 | screening | diagnosis |
| 队列 | 12 万 + 6.5 万 + 325 前瞻 | **267** + 244 |
| 对照 | 元数据模型、尿蛋白试纸 | 肾活检 |

硬塞进一张卡的后果：病种变成两个病名的拼接、场景在"基层"和"专科"之间必须二选一
（必错一个）、人群格里两拨互斥的人打架 —— **而这几格全在准入层，卡一混后面全错。**

## 6. 准入 ≠ 检索（最容易被误解的一节）

"只有 gating 参与"这句话**只对准入成立，对检索不成立**。

| | **检索（召回）** | **准入（门控）** |
|---|---|---|
| 问题 | 去 API 里**用什么词查**、结果怎么排 | 库里这份指南**适不适用** |
| 要求 | **宁多勿少**，词越多召回越好 | **要准**，错一个就拿错标准要求作者 |
| 用哪层 | **descriptive 为主** + gating 的病种/场景 | **只用 gating** |
| 出错后果 | 检不到 / 检到噪声，**看得见** | **静默错配，看不见** |

同一个"人群"，两边用的是**两份不同的值**（`retrieve.py:60`）：

```python
# 检索侧要召回，用描述层的人群原文；门控侧要准确，用受控的 target_population。
# 二者刻意不同源——这正是分层卡要解决的问题
```

实际拼出来的查询串（DKD claim_1，`[strict]` 档）三块 AND 起来，**两块来自 descriptive**：

```
TITLE_ABS:"diabetic kidney disease"                        ← gating（强制主题短语）
  AND (screening OR retinal OR fundus OR low-resource …)   ← descriptive（干预软约束）
  AND (…人群词…)                                            ← descriptive + gating
```

查不到还有**降级阶梯**：`strict → no_pop → no_interv → phrase → tokens_and`，
逐档放松直到有命中；**最后一档绝不用裸词串**（会检回鼻窦炎指南那种东西），
全落空就返回空列表 —— 宁可空手也不给审稿模型喂垃圾。

### 字段去向总表

| 卡里的字段 | 层 | 去向 |
|---|---|---|
| `condition.primary.label` | gating | 检索强制短语 **+** 指南病种门控 |
| `condition.excluded` | gating | 与指南 scope 做排除比对 |
| `population.age_group` | gating | 指南人群门控（成人指南 vs 儿科论文硬拦） |
| `care_setting` | gating | 指南场景门控 + 检索人群约束 |
| `clinical_task` | gating | 指南场景/职权门控 |
| `evidence_stage` | gating | 报告清单越级拦截（C1 论文不该被 CONSORT-AI 要求） |
| `intended_use` | descriptive | **检索干预词 + 报告清单启停** |
| `model_input` / `model_output` | descriptive | 同上 |
| `deployment_claim_level` | descriptive | 报告清单启停 |
| `target_population` | descriptive | **检索人群约束** |
| `claimed_benefit` | descriptive | 已进 query_context，当前无连接器读取 |
| 其余 descriptive、全部 `note` | descriptive | **程序不碰**，只给人读 |

**语言规则由这张表推出来**：凡是被程序消费的（上表前 11 行里的自由文本字段），
**必须写英文**，因为它们会被拼进英文查询串、或被英文词表匹配。写中文不报错，
只**静默失效** —— 实测踩过两次：写中文关掉整层报告清单（检索 99 条→14 条）、
人群约束被切成中文碎片还被加了复数 `s`。

**分界是"程序读不读"，不是"重不重要"。** `comparator`、`benefit_gap`、
`clinical_context`、所有 `note` 继续写中文，程序确实不碰。

## 7. 库里其实是两种东西

`clinical_sources.yaml` 里 41 个源，工作方式完全不同：

### 第一类：在线 API 源（4 个）

EuropePMC / ClinicalTrials.gov / openFDA / WHO GHO。**真的检索** —— 现场发请求，
对面几千万篇。词越多越好，descriptive 大量参与。

### 第二类：离线策展库（现在 16 份文档）

USPSTF 142 条、WHO IRIS 3 份 98 条、学会 CPG 6 份、报告清单 7 份。

**这一类根本不是"检索"，是"逐份过筛"** —— 库里就这么十几份，程序拿着卡
一份份问"这份适不适用"：

```
USPSTF《肺癌筛查》     → 卡的病种是糖尿病肾病  → ⛔ 不匹配
WHO《产程照护》        → ⛔ 不匹配
韩国《脓毒症 CPG》     → ⛔ 不匹配
TRIPOD+AI 报告清单     → 预测模型开发+验证    → ✅ 启用，52 条全出
CONSORT-AI 清单        → 卡是 C2，它管 C4     → ⛔ 拦截，打印"套用属越级要求"
```

**这里不存在"词不够查不到"的问题** —— 压根没在查，是在做判断题。
而判断题必须用受控值。**这就是 gating 层要小、要受控的原因。**

> ⛔ 不适用时**必须打印理由**。"没命中"和"不该命中"是两回事，
> 混在一起会让缺口报告失真。

## 8. 四种 `status`，后果完全不同

每条证据都要标状态。这是整套流程里最容易被忽略、但影响最大的设计。

| status | 含义 | 后果 |
|---|---|---|
| `explicit` | 论文明写，有可定位引文 | 正常 |
| `inferred` | 没明写但可推断 | 可接受，**`note` 必填**：依据什么、依据在哪 |
| `absent` | **论文确实没写**（全文找过） | **这是审稿发现**，进缺口报告 |
| `not_extracted` | **没找到 / 材料没给全** | **这是故障**，硬错误，卡不得进检索 |

后两个看起来像同一件事，其实相反。**把故障标成 `absent`，等于把系统自己的问题
算成论文的缺陷 —— 而且这么干，系统的评测分数看起来还更好。**

同理，`condition.primary` 为空也分两种：`scope_type: disease` 且没命中 = **缺口**
（该补库）；`scope_type: care_process`（跨专科流程类研究）= **不适用**（不计入缺口）。
混淆二者会让流程类论文撑大"覆盖不足"的数字，掩盖真正缺指南的病种。

## 11. 贯穿全局的一条思路

**凡是"成卡之后看不出来"的错误，都要用程序堵死，不能靠"记得别这么干"。**

清点一下这类错误分别是被什么堵住的：

| 错误 | 堵它的东西 |
|---|---|
| 引文被模型改写 | `evidence.py` 的 `str.find` |
| 引文用省略号拼接 | `evidence.py` 硬拒绝 |
| 数字来自别的主张的队列 | 阶段一 `uses_cohorts` 白名单 + 阶段二 `cohort_id` 必填 |
| 抽取故障被记成"论文没写" | `not_extracted` 与 `absent` 分开 + ④不过硬退回 |
| 核查者被上一轮结论带偏 | 新进程 + 白名单装配（`needs=[]`） |
| 指令里夹带被审论文的场外信息 | `_audit_stage3_leak()` 装配时自动扫 |
| 分级错一级导致整条路由错 | `evidence_stage` 由程序从七个事实映射 |
| 病种格被污染导致门控静默失效 | `validate_card()` 硬错误 |
| **被消费字段写中文导致整层静默关闭** | **目前只写在 prompt 里，程序还没检查** ← 已知缺口 |

最后一行是现在唯一还靠"模型自觉"的一条，堵法见
[`PROMPT_REVISION_2026-08-01.md`](PROMPT_REVISION_2026-08-01.md) §5 待办。
