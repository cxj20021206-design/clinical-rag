### 一条没被检验的预期

ICLR 篇的 run README 预期"库里的**成人 CPG 应被人群门控硬拦**"。
实际：9 份 CPG **全部先被病种门控拦下**，人群门控根本没轮到执行。

这不是预期失败，是**预期没被检验** —— 库里目前没有任何糖尿病/低血糖指南，

（例如成人脓毒症指南 vs 儿童脓毒症论文，`examples/claim_card_neonatal_sepsis.yaml`

## 4. 实跑撞出来的三个既存缺陷（都已修，都有回归）

这三个都不是新 prompt 引入的，是**新 prompt 产出的卡第一次走到那些分支**才暴露。

### ① `validate_card()` 与 stage2 规则⑨直接打架

规则⑨明令 `evidence_stage` 留空、由程序从 `evidence_basis` 七事实映射，
而 `validate_card()` 仍硬性要求它 ∈ C0–C4 → **新 prompt 产出的卡一律过不了门**。

此前没暴露，只因既有卡全部出自旧 prompt、自己写了 `"C2"`。

修法（`claim_card.py`）：留空 → 用映射填上并记 warn 说明"此值来自程序判定表"；
**已声明则仍只报警不覆盖**（"只接入不消费"对声明值不变）。

### ② `evidence.py: from_mineru()` 漏读一半的块类型 —— 合法引文被判成故障

只读了 `("text", "table_body", "table_caption", "img_caption")`，而 MinerU 3.x 用的是
**`image_caption`（不是 `img_caption`）**、`chart_caption`、`chart_footnote`、`content`、
`table_footnote`、`code_body`、`list_items`。ICLR 篇有 7 张 chart、3 张 image，
**它们的图注在核验语料里整体缺失**。

后果：模型从图注取的合法引文定位失败 → 判 `not_extracted`（硬错误）→
按流程要退回重填一张本来正确的卡。**这与"拿 MinerU 抽卡却用 pypdf 核验"是同一类错误，
只是发生在 MinerU 内部。**

修法：改白名单 + **未知键告警**（MinerU 换 schema 时会吵，不再悄悄变窄）。实测告警可触发。
修完 ICLR claim_1 从 19/20 变 20/20。

### ③ 研究设计推断用裸子串 —— `ct` 命中 `characters`

`_IMAGING_KW` 里的 `"ct"` 以裸子串匹配，命中了 ICLR 卡 `model_input` 里的
`"chara`**`ct`**`ers"`，把一篇**血糖时序**论文判成 `medical_imaging_ai`
→ CLAIM 影像清单被错误启用、报成 🕳（适用但零摄入＝真缺口）→ **凭空撑大缺口报告**。

更要命的是 `"predi`**`ct`**`ion"` 同样含 `ct`，意味着**几乎任何预测模型论文都会中招**。

修法：缩写（≤3 字符）首尾都封边界，词干只封词首。
与 §6e 的 `injury` 命中 `acute kidney injury`、§6d 的 `ultrasound` 命中儿科超声指南
是同一类错误 —— **短词当判别信号必须先划边界**。

## 5. 一个没决过的策略：会议论文拿不到投稿日

ICLR 篇是匿名双盲送审稿：无 `Received:`、无 `Accepted:`、无文献检索截止日。
阶段一按阶梯走到第 4 档 `unavailable`，**并明确拒绝用参考文献最新年份反推** —— 这是正确行为。

后果：`validate_card()` 硬报错"submission_date 缺失"，**卡进不了检索**。

处理（本次）：
- 抽取产物 `03_cards/*.yaml` **保持原样、保持不通过硬门**；
- 另由脚本 `05_retrieval/_make_operator_variant.py` 生成带日期的变体，
  仅供跑通下游演示，文件名带 `_operator_date_` 前缀、卡内头部留痕，
  `basis` 取值 `venue_deadline_external`（**不在阶梯四档内**，模型不得推断）。

**这需要你拍板**，见 `docs/STATUS_2026-08-02.md`。
