## 执行顺序

```
① 程序：PDF/Word/HTML → 分页纯文本          （evidence.SourceDoc）
② stage1_overview.md   全文 → paper_overview.yaml
③ stage2_fill_card.md  每个 claim_candidate 各跑一次 → claim_card yaml
④ 程序：python3 evidence.py <card>          引文逐条字面定位
⑤ 程序：python3 claim_card.py <card>        枚举与逻辑校验
⑥ stage3_adversarial_check.md  → 核查报告（**不改卡**）
⑦ 人：只确认五个高危字段
```

④⑤ 不过就回 ③ 重填，**不要手工改卡去迁就校验**——那是把故障洗成"论文没写"。

## 五条贯穿所有阶段的硬约束

### 1. 只依据提供的论文材料

不得使用任何论文之外的知识补全字段：不得根据病种常识推断人群，不得根据期刊惯例推断
场景，不得根据模型名推断用途。找不到就按 `absent` / `not_extracted` 如实标。

### 2. 取证必须在全文范围，且**摘要不是默认取证来源**

摘要是作者对论文的**自我概括**，它压缩掉的恰恰是门控最需要的东西：纳入排除标准、
队列构成、对照的定义、场景的实施细节。"不得假定信息位于固定章节"这句话描述的是愿望，
下面才是可执行的动作：

- **以下字段的引文不得取自摘要、标题或 Research in context 之类的概括方框**，
  必须取自正文（Methods / Results / 表格 / 图注 / 附录）：
  `population.*`、`care_setting`、`descriptive.comparator`、`evidence_basis` 的七个事实。
  这些字段在摘要里必然是压缩过的；摘要里有的，正文里一定有更完整的版本，取正文那个。
- 其余字段允许取自摘要，但**若正文里存在更具体的表述而你用了摘要版本，视为取证不足**。
- 找不到正文版本时，不要退回摘要版本充数——按 `absent`（论文确实没写）或
  `not_extracted`（你没找到）如实标。两者的区别见硬约束 5。

### 3. 引文必须是**复制**来的，不是重述来的

获取引文的动作是"定位 → 原样复制"，不是"回忆 → 写出"：

1. 先在给你的文本里找到那段话；
2. 把它**整段照搬**，包括 PDF 抽取伪影（合字 `ﬁ`/`ﬂ`、跨行断字 `recommen-dation`、
   丢失的连字、异常空格、Unicode 同形字符）——**这些必须原样保留**，
   归一化由程序做，不由你做；
3. 写完后**回到原文再搜一次你写下的字符串**。搜不到就说明你重写了它，改回去。

禁止：省略号、改写、补全缩写、修正原文错字、把两处不相邻的句子拼成一条引文。

**引文必须是连续片段。** 给不出连续片段（例如表格被解析成交错的行）时，
不要拼接——按 `inferred` 填值并在 `note` 里写明依据，或标 `not_extracted`。

### 4. 一条引文只能支持它真正在讲的那个字段

一句话被同时当成三四个字段的证据，等于这些字段实际上只有一个证据。
自检问法：**这句话的主语，是不是我要填的那个东西？**

- 讲"整个领域正在努力开发某类检测"→ 支持不了"**本系统**用于某场景"（那是领域现状，
  不是本研究）；
- 讲"更简便的检查对某某科医师有用"→ 支持 `intended_user`，支持不了 `care_setting`
  （句子里根本没有场所词）；
- 讲"本研究纳入做过某项检查的患者"→ 支持**样本入组来源**，
  支持不了 `population`（模型将被用在谁身上）。

同一句话确实同时讲了两个字段时，分别写两条 `provenance` 条目，各自截取真正相关的那部分。

### 5. `status` 必填，四种状态不可互相顶替

| status | 含义 | 后果 |
|---|---|---|
| `explicit` | 论文明写，有可定位引文 | 正常 |
| `inferred` | 没明写但可从原文合理推断 | 可接受，**`note` 必填：依据什么、依据在哪** |
| `absent` | **论文确实没写**（全文找过） | **这是审稿发现**，会进缺口报告 |
| `not_extracted` | **你没找到 / 材料没给全** | **这是故障**，硬错误，卡不得进入检索 |

- 每条 `provenance` 条目**都要写 `status`**，一条不许省。不写不等于 `explicit`，
  不写等于分不清"论文明写"和"忘了填"。
- 只搜了摘要就放弃 → `not_extracted`。全文都找过仍无 → `absent`。
- 材料本身没给全（附录未取到）→ `not_extracted`，**不许用其他部分的数据代填**。
- 把故障标成 `absent`，等于把系统的问题算成论文的缺陷，而且分数看起来还更好。
- **本项目自己的标签词不构成 `explicit` 的依据**：`C2`、`primary_care`、`screening`
  这些枚举值是我们的词汇，论文里不存在。引文要证明的是**事实**（"有独立外部队列"），
  不是标签（"这属于 C2"）。事实明写但标签由我们判定 → `inferred` + `note` 写判据。

## 阶段三必须换上下文

`stage3` 的价值在于**独立**。同一个上下文里跑，执行者已经看过阶段二的推理，会顺着走
（"同血统偏好"）。**正确做法是新开一个会话**，只喂 `stage3_adversarial_check.md` +
卡 + 论文全文，不喂任何阶段一/二的产物或对话。

在同一上下文里跑出来的核查结果只能当**下界**：它挑出来的问题是真的，它没挑出来的
不能算没有。

实测过的两条性质，下游必须知道：

- 隔离与否的差别不只是"多挑出几条"。非隔离运行可能把核心问题判成 pass，
  也可能给出**方向相反**的结论；
- 隔离运行之间"抓到什么"稳定，"抓到几条 / 判多重"不稳定——
  下游只能采信**发现的集合**，不能采信条数与严重度。

**装配阶段三的材料时，不得混入任何关于某篇具体论文的场外信息**——包括 prompt 文件里
举的例子、以往对同一篇论文的核查报告、流程事故复盘。隔离不是"别给上一阶段的产物"，
是"别给任何关于这篇论文的场外信息"。
