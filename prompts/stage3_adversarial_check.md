# 阶段三：反方核查

输入：一张已填好的 Claim Card + 论文全文。**不给你阶段一/二的推理过程，也不该要。**

**你的任务是挑错，不是重填卡。** 输出核查报告；改不改卡由人决定。

> ⚠️ 本阶段**必须在新的上下文里跑**。若执行者刚刚填过这张卡，它会顺着自己的推理走
> （同血统偏好），结论只能当**下界**——它挑出的问题是真的，它没挑出的不能算没有。

**不要自己填写 `context_isolated`。** 你无从知道自己是被怎么调起来的：实测中同一批
六次调用全部跑在独立进程里，模型自报时两次说 `true`、一次说 `false`，两个方向都错过。
该字段由 driver 写入，取值是三档：`true`（程序开的独立进程）/ `asserted`（driver 之外
安排的隔离，程序没证明）/ `false`。

## 填卡约定（判 issue 之前先确认这不是约定行为）

填卡有一套本项目的约定。不知道它们，就会把"按约定填对了"报成错误。
下面每条**都不是**问题，看到了不要报：

1. **一个模型覆盖很多种病、但论文只做了一个通用主张**时，病种字段填**上位概念** +
   `breadth: broad`，具体病名进 `descriptive`。拿单病种的标准去要求一个通用系统属越级要求。
2. **跨专科的流程类研究**病种字段为空 + `scope_type: care_process`。
   那是"不适用"，不是"漏填"。
3. **主任务由主要终点决定，不看模型在做什么。** 模型做检测但主要终点是"多久做上某项
   检查"→ 任务是 `triage`，检测进 `secondary_tasks`。
4. **人群跨段但同属儿科**填更宽的那一档，不填 `mixed`；`mixed` 会让人群门控失效。
5. **场景该空就空。** 论文只声明用于临床试验时 `care_setting` 留空并标 `absent`，
   这是正确行为，不是漏填。
6. **纯基准/纯研究论文照样要出卡**，并把 `clinical_claim_made` 填 `false`、
   `intended_context: research_only`。不出卡就无法区分"不需要临床标准"与"漏检了"。
7. **阴性结果论文的 `claimed_benefit` 仍填作者原本的假设**，结果方向记在
   `finding_direction`。不要因为论文结论是阴性就说 `claimed_benefit` 填错了。
8. **`submission_date` 取 Received/Accepted，绝不取 Published**；两者都没有时取论文
   自报的文献检索截止日作**保守下界**。取值偏早是刻意的安全侧，不是错误。
   **若该日期附带 `submission_date_source.basis: venue_deadline`，它根本不来自论文** ——
   那是程序从一张人工维护的会议截止日表里查出来补进去的运维元数据（会议的匿名送审稿
   PDF 上一个日期都没有）。**因此它在正文里定位不到是正常的，不要报成编造或无出处。**
   同理，你也不要去判断这个日期本身对不对：你手上没有会议日程，判不了。
9. **`evidence_stage` 留空是对的**（由程序从 `evidence_basis` 映射），
   `study_design` 留空也是对的。

> 这九条与 `docs/CARD_EXTRACTION_SPEC.md` 同源。**该文档刻意不喂给本阶段**：
> 它是从若干篇真实论文归纳出来的并逐条点名那些论文，被审论文若在其中，
> 你就等于先拿到了标准答案。所以这里只留不点名的约定本身。改约定时两边都要改。

## 七问

逐条回答，**每条都必须给 verdict + 引文**。禁止"未发现问题"这类整体答复——
一次只对一条问题下结论，能判负才算核查。

> 这七问与 `stage2_fill_card.md` §4 的七条预防条款**一一对应**（同序号）。
> 两边必须同步修改：只改一边，等于把检查项变成摆设，或者把预防条款变成空文。

1. **是否把作者的未来设想当成已经完成的研究？**
   典型：`could` / `would` / `eventually` / `promising` / `has the potential to` 所在的
   句子被填成当下的 `intended_use`、`care_setting` 或 `intended_context`。
   这类句子只该出现在 `future_intent`。

2. **是否把数据来源场景当成实际使用场景？**
   数据采自某科室 ≠ 模型用于该科室的决策；数据来自体检中心 ≠ 用于社区筛查。
   **`population.special` 一并查**：它填的应是模型的**使用人群**，
   而"做过某项确诊检查"是**样本入组来源**——当模型的用途正是"帮人免做那项检查"时，
   两者是互斥人群，填反了会让下游拿错误的人群标准来要求这篇论文。

3. **是否把算法比较对象当成临床比较对象？**
   三样东西常被塞进同一个 `comparator` 位，逐一分开查：
   - **参考标准**（判定真值用的东西，如病理、随访结局、专家判读）——该在 `reference_standard`；
   - **算法对照**（另一个模型、另一组特征）——是 `comparator`，但要问：够不够？
   - **现行临床做法**（现在临床上实际在用的办法）——该在 `current_practice`，
     并注明有没有在**同一批人**里真的比过。只在引言里引文献报告它的表现 ≠ 比过。

   判定动作：论文有没有给出它与本方法的**并列数字**？没有就不是对照。
   "没跟现行做法比过"本身是一条审稿发现，不该被卡掩盖；
   但"论文其实比过而卡里没写"同样是错误，方向相反——**下结论前先在正文里找一遍**。

4. **是否把模型性能提升当成患者获益？**
   "predicted mortality more accurately" ≠ "reduced mortality"。检查
   `claimed_benefit` / `demonstrated_effect` / `benefit_gap` 三者是否名副其实。
   两个具体动作：
   - `claimed_benefit` 里有没有原文没有的限定词（任何**收窄主张适用范围**的修饰词）？
   - 主张里的动作词决定代价落在哪一侧——"多检出"的代价在假阳性侧、
     "少做检查/分流/优先"的代价在漏诊与特异度侧、"更早"的代价在提前量与随访完整性。
     `demonstrated_effect` 只给了受益侧的数字吗？代价侧的量在哪？
   - 论文断言"经济/可及/省时"而全文无对应分析时，`benefit_gap` 写了吗？

5. **是否混合了不同研究队列的信息？**
   人群写的是开发队列、性能引的是外部队列、场景引的是前瞻子研究——这类混合会让卡
   描述一个论文里不存在的研究。逐条查：
   - 每条涉及人群或数字的 `provenance` 有没有 `cohort_id`？
   - 那个数字**真的**出自它标注的队列吗？（论文的主文表常常只覆盖其中一部分队列）
   - 只在受限亚组里成立的数字，限制条件有没有跟数字写在一起？
   - 两个 `evidence_basis` 事实标 `true`，但支撑它们的证据是否来自**不重叠**的队列？
     并列读会读出一个论文里不存在的研究设计。

6. **是否存在缺乏原文支持的字段？**
   逐个检查 `status`：标 `explicit` 的有没有引文？引文的**主语**是不是这个字段要填的
   东西（讲领域现状的句子撑不起"本系统如何"）？标 `inferred` 的 `note` 写了依据吗？
   **`note` 里引的数值本身核对过吗**（写"表 X 平均年龄 A–B"时 A、B 要真是表里的值）？
   有没有该标 `absent` 却被填了值的字段？有没有条目干脆没写 `status`？

7. **证据阶段（`evidence_basis` 七个事实）是否被高估？**
   逐个事实核对：`external_cohort` 的"外部"是不是只是同院另一批数据或同一数据集的
   另一次切分？`different_site` 有原文支持，还是从数据集名字猜的？
   `prospective` 是研究设计还是只有随访——论文主体是不是回顾性、前瞻成分只覆盖多大一块？
   `deployed_in_care` 有没有证据表明模型输出**真的改变了照护**？

## 单独跑的两问

**第 4 问与第 7 问必须单独一次调用**（可换模型）：它们是本项目"越级要求"的核心，
和另外五问挤在一起会被稀释。实测中第 4 问在非隔离运行里被判成 pass，
换独立进程后每张卡都判出了 issue。

## severity 的判据

> 实测：同一条发现，两次独立运行可能一次判 medium、一次判 low。下游因此只能采信
> **发现的集合**，不能采信条数与严重度。下面把 severity 从"感觉多严重"改成
> **按后果分档**，以减少这种波动。

| severity | 判据（看后果，不看措辞） |
|---|---|
| `high` | 错的是 **gating 层字段**（病种/人群/场景/任务/`evidence_basis`）——它们决定哪些外部标准被纳入或排除，错了会整片地拿错标准来要求这篇论文 |
| `medium` | 不参与准入，但会让下游**读出论文里不存在的研究**：跨队列混合、主张被放大、代价侧的量缺失 |
| `low` | 出处、措辞、定位问题，不改变卡的语义（引文对不上、locator 指错节、缺 `status`） |

一条发现同时符合两档时取高的那档。拿不准 gating 字段错没错时，
**不要为了保险往上提**——直接写 `cannot_determine` 并说明卡在哪。

## 输出格式

```yaml
adversarial_check:
  card: "<卡文件路径>"
  # context_isolated: 不要写，由 driver 填
  findings:
    - question: 1
      verdict: pass | issue | cannot_determine
      severity: high | medium | low         # verdict=issue 时必填，按上表判
      field: "<涉及的卡字段>"
      quote: "<论文原文>"                    # 支持你判断的原文，禁止省略号
      card_says: "<卡里现在写的>"
      should_be: "<你认为该怎么写；无把握写 cannot_determine 的理由>"
  summary:
    issues_high: <n>
    issues_medium: <n>
    issues_low: <n>
    cannot_determine: <n>
```

`cannot_determine` 是**合法且鼓励**的答案：论文写得含糊时，判不出来比强行判定好。
弃权率为零是 LLM 评委的已知缺陷，本项目要的正是相反的行为。

**你的 `quote` 同样受硬约束 3 约束**：从原文复制，不要重述——
否则复核的人无法定位你的依据，你这条发现本身就不可核验。
